# 标注后台：完整项目功能清单

上一份 [01-fastapi-learning-path.md](./01-fastapi-learning-path.md) 回答「先按什么顺序学、每步写什么」。这份回答「一个能上线的标注后台管理系统，功能要齐到什么程度」。

两份文档的关系：

- 学习路径：垂直切片，保证每一天都有能跑的接口。
- 完整项目：水平清单，避免上线前才发现缺用户、缺导出、缺任务流。

状态标记：

| 标记 | 含义 |
|---|---|
| 已覆盖 | 学习路径某一步会做到最小可用 |
| 完整项目 | 学完 0–10 步之后再做，生产需要 |
| 按需 | 业务真出现再做，不是后台标配 |

## 8. 建议的产品模块切分

完整项目按模块开发时，用这个切，不要按「再写一个 CRUD」切。

```text
平台
  配置 / 信封 / 错误 / 日志 / 审计 / 健康检查 / 文件

身份
  登录 / 用户 / 租户 / 角色 / Casbin

系统管理
  字典 / 参数 / 操作日志 / 登录日志 / 导出

标注核心
  项目 / 标签体系 / 数据集 / 样本
  任务 / 分配 / 标注结果 / 质检

标注增值
  预标注 / 统计看板 / 异步导入导出 / 协同
```

依赖顺序：平台 → 身份 → 系统管理 → 标注核心 → 标注增值。  
学习路径走完，约等于「平台最小集 + 身份缝 + 一个项目 CRUD」。其余都是这份清单里的「完整项目」。

## 9. 完整项目的推荐实现顺序

学完 0–10 步之后，如果要把仓库做成可交付后台，按这个顺序补，而不是按兴趣跳：

1. **把登录产品化**：密码哈希、登出、刷新令牌、登录日志、登录限流。
2. **权限可运营**：Casbin 策略入库、角色管理接口、前端菜单树。
3. **项目成员 + 标签体系**：没有标签体系，后面的任务是空的。
4. **数据集 + 对象存储 + 导入队列**：标注后台从此才像标注后台。
5. **任务状态机 + 分配 + 提交 + 质检**：核心闭环。
6. **导出 + 看板**：给项目经理用。
7. **恢复软删、操作日志查询、字典、系统参数**：管理台收尾。
8. **测试 / Docker / CI / 安全头**：能交给别人跑。

预标注、协同、SSO、2FA、邮件邀请，都放在闭环能跑之后。

## 10. 刻意不放进完整项目默认范围

这些常见，但不该变成「标注后台必须有」：

- GraphQL / tRPC（REST + OpenAPI 足够）
- 微服务拆分（先单体）
- 每租户独立数据库（先共享库 + tenant_id）
- 计费 / Stripe
- 社交登录
- 完整 APM 平台
- 自研工作流引擎

需要时再开，不要写进第一版范围。
